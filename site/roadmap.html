Production accounts

Code ready; deployment blocked

  • Account client, login, registration, profile, activity, and daily reward contracts exist.
  • The secure Phase 345 Node/Azure SQL backend contract exists.
  • Demo mode remains clearly labeled while production API configuration is empty.
  • Production requires an approved HTTPS host, Azure SQL migration execution, and secrets stored outside GitHub.

GitHub does not contain or request production database passwords, JWT secrets, or private cloud credentials.

Presence and seats

Contract ready; multi-device deployment pending

  • Unique room presence and transactional seat ownership contracts exist.
  • Reconnect, heartbeat, duplicate-player suppression, and seat release are implemented.
  • Local simulation remains labeled as simulation.
  • The Phase 349 API and SQL migration must be deployed before authenticated multi-device acceptance.
  • Poker cards, pots, balances, and winners are not synchronized by the presence layer.

Server-authoritative poker

New secure backend required

  1. Move deck generation, private cards, turns, betting, pots, winners, and balances to a room server.
  2. Add authenticated actions, reconnectable snapshots, event logs, and idempotency.
  3. Prevent client-side card and balance manipulation.
  4. Pass multi-device hands, disconnects, reconnects, and concurrency tests.

The current Phase 336 engine is authoritative only inside the local browser session.

Unity production client

Blueprint exists; implementation remains future work

  1. Use the protected account, profile, inventory, presence, room, and poker contracts.
  2. Convert approved assets into optimized Unity-ready formats.
  3. Build scenes, prefabs, Meta input adapters, networking authority, and performance budgets.
  4. Produce signed Quest/Android/desktop builds through private build infrastructure.

Release decision rules

  • No local simulation is described as production internet multiplayer.
  • No physical-device acceptance is claimed from Chromium emulation.
  • No database secret, signing key, private key, or password is committed to GitHub.
  • No APK update is visible until a signed package, checksum, and upgrade test exist.
  • No server-authoritative poker claim is made until a secure room server passes multi-device acceptance.

The machine-readable authority record is maintained at /docs/SVR_RELEASE_STATUS.json.
